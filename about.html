FAQ & License

Straight answers about using and generating skills, how verification works, and what you can do with the files.

Frequently asked questions

Do I need Python or API keys to use skills?

No. Skills are static Markdown and JSON files. You can read them with any programming language — no Python, no API keys, no database, no embedding models.

Do I need API keys to generate skills?

Yes. Generating skills is a BYOK model: contributors supply at least one LLM API key (DeepSeek, Kimi, GLM, or Gemini) and run the pipeline locally. See For Contributors.

How do quotes get verified?

A three-layer validation suite: fuzzy quote verification against the source chunk (rapidfuzz), schema validation of the skill's frontmatter (Pydantic), and a hallucination guard that checks for invented speakers, claims, or quotes (Gemini as LLM-as-judge). Skills that fail move to skills/_failed/ and cannot be published. GitHub Actions re-runs validation on every pull request.

Can I use only some skills, not all of them?

Yes. Pick and choose the skills relevant to your use case. The by_category and by_tag lookups in skills-index.json make filtering easy, and the /category and %tag signal prefixes route queries to a subset.

What does a low confidence score mean?

Confidence is a 0.0–1.0 score computed from cluster metrics — not the LLM's opinion. A low score means fewer sources corroborated the advice, or sources disagreed. The skill is still valid but should be treated as less authoritative; consider pairing it with related higher-confidence skills.

How often are new skills added?

Skills are added manually by contributors — there is no fixed schedule. Watch the repository or check Releases for updates.

What's the difference between skills-index.json and similarity_matrix.json?

skills-index.json is a lookup table — find skills by ID, tag, or category. similarity_matrix.json is a relationship matrix — pre-computed cosine similarity between every pair of skills, used for fuzzy search and related_skills.
